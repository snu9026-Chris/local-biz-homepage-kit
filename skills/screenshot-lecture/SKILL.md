# 스크린샷 → 강의자료 (실시간 매칭)

## 0. 이 스킬이 푸는 문제

강의자료를 만들려고 나중에 스크린샷을 몰아서 정리하면 **"이게 몇 번째 단계 화면이었지?"** 에서 무너진다.
파일명은 `KakaoTalk_20260815_1349.png`, 순서는 뒤죽박죽, 왜 찍었는지는 기억에 없다.

그래서 **작업하는 그 순간에** 매칭한다. 대화 맥락이 살아 있을 때가 유일한 기회다.

```
  사용자                          Claude
 ─────────                      ─────────
  작업 시작  ──────────────▶  ① 촬영순서표(원장) 먼저 만든다
                                 «앞으로 밟을 단계»를 예측해 체크리스트로
      │
  한 단계 실행
  화면 캡처해서 폴더에 툭  ──▶  ② 이미지를 실제로 열어본다 (추측 금지)
  "넣었어"                      ③ 대화의 «직전 단계»와 대조해 판정
      │                         ④ NN_설명.png 로 rename
      │                         ⑤ 원장에 ⬜→✅ + 원본 파일명 기록
      ▼
  전 단계 완료  ────────────▶  ⑥ lecture-materials 스킬로 슬라이드 산출
```

**역할 분담**: 사용자는 «찍어서 넣기»만 한다. 이름·순서·설명은 전부 Claude 몫이다.
사용자에게 파일명 규칙을 지키라고 요구하지 마라 — 그걸 요구하는 순간 이 스킬은 실패한 것이다.

---

## 0.5. ★ 첫 동작 — 폴더는 Claude 가 만든다 (사용자에게 시키지 않는다)

이 스킬이 발동하면 **다른 무엇보다 먼저, 묻지 말고 폴더부터 만든다.** 사용자가 «폴더 만들어» 라고
말했든 «이거 강의자료 쓸거야» 라고만 했든 똑같다. 사용자가 할 일은 «찍어서 넣기» 뿐이다(§0 역할 분담).

```
스킬 발동  →  ① 프로젝트 루트 확인
              ② `<루트>/가이드라인 스크린샷/00_촬영순서.md` 를 Write 로 생성 (폴더가 같이 생긴다)
              ③ 사용자에게 «절대경로 한 줄» + «그냥 넣으세요» 통보
```

- **금지**: "폴더 만들까요?" 라고 되묻기 / "이 경로에 폴더를 만들어 주세요" 라고 사용자에게 시키기.
- 주제·범위를 모르면 원장의 표는 비워둔 채 만들고, 표는 대화가 진행되며 채운다.
  **폴더 생성을 «계획이 정해진 뒤»로 미루지 마라** — 사용자는 그 사이에 이미 첫 화면을 찍는다.
- 이미 폴더가 있으면 만들지 말고 그대로 쓴다(원장 덮어쓰기 금지 — 기존 매칭 기록이 날아간다).
- 만든 직후 사용자에게 알릴 것 (경로는 클릭·붙여넣기 가능한 절대경로로):

  > `/Users/.../<프로젝트>/가이드라인 스크린샷` 에 폴더 만들었습니다.
  > 작업하면서 화면 캡처를 여기 넣어두세요 — 파일 이름은 아무거나 상관없고, 폴더는 제가 매번 확인합니다.

## 1. 폴더 규약

```
<프로젝트 루트>/
  가이드라인 스크린샷/
    00_촬영순서.md          ← 원장. 계획 + 매칭 결과가 여기 다 있다
    01_가비아-도메인목록.png
    02_가비아-DNS관리툴-진입.png
    ...
```

- 폴더는 **프로젝트 루트 안**에 둔다. 바탕화면에 만들지 마라 (전역 규칙 #7).
- 폴더명은 한글 `가이드라인 스크린샷` 을 기본으로 한다 — 사용자가 탐색기에서 찾는 폴더다.
- **폴더 생성은 Claude 가 한다 — 사용자에게 만들라고 하지 마라 (§0.5).**
  방법은 Write 도구로 `00_촬영순서.md` 를 쓰는 것 (부모 디렉터리가 자동 생성됨).
  `mkdir` 을 PowerShell로 치면 한글 폴더명이 콘솔 인코딩에 걸린다. §5 참조.

---

## 2. ★ 먼저 촬영순서표를 만든다 (작업 시작 전)

**스크린샷이 들어오기 전에** 원장부터 만든다. 이게 이 스킬의 심장이다.

이유: 사용자는 "뭘 찍어야 하는지" 모른다. 표가 없으면 아무거나 찍고, 정작 강의에 꼭 필요한
**«전/후 대비 화면»**(설정 전 빈 화면, 설정 후 채워진 화면)이 빠진다. 그건 나중에 재현이 불가능하다.

원장 양식:

```markdown
# 가이드라인 스크린샷 — 촬영 순서표

> **주제**: <무엇을 가르치는 자료인가>
> **범위**: <어디서부터 어디까지 — 예: 도메인 구매 이후 ~ 접속 성공까지>
> **사용법**: 순서대로 하면서 화면을 찍어 이 폴더에 넣으세요. 파일 이름은 아무거나 상관없습니다.

| # | 찍을 화면 | 파일명 (예정) | 상태 |
|---|---|---|---|
| 01 | <어느 화면의 무엇> | `01_대상-화면.png` | ⬜ |
| 02 | ... | ... | ⬜ |
```

**표를 짤 때 반드시 넣을 4종**

| 종류 | 왜 필요한가 | 예 |
|---|---|---|
| **진입 경로** | 학생이 그 화면을 «못 찾아서» 막힌다 | 메뉴 어디를 눌러 들어가는지 |
| **설정 전** | 대비가 없으면 뭘 바꿨는지 안 보인다 | 비어 있는 레코드 목록 |
| **입력 순간** | 어느 칸에 뭘 넣는지가 핵심 | 값 입력된 폼 |
| **설정 후 / 성공** | 학생이 «내가 제대로 했나»를 판정할 기준 | 초록 체크, 최종 접속 화면 |

**실패 신호**: 표가 «성공 화면»만 있고 «전 상태»가 없다 → 다시 짜라.

## 3. 실시간 매칭 절차 (스크린샷이 들어올 때마다)

### ⓪ ★★ 매 턴 폴더를 스캔한다 — 이걸 빼면 스킬이 죽는다

**Claude 는 파일이 폴더에 추가돼도 알림을 받지 않는다.** 사용자가 말해주기 전엔 모른다.
그런데 사용자는 "작업하면서 그냥 넣는다" — 그게 이 스킬의 전제다. 두 사실이 충돌한다.

> **해결**: 촬영 세션이 시작된 뒤에는 **응답할 때마다 폴더를 `ls` 한다.** 사용자가 스크린샷 얘기를
> 안 꺼내도 한다. 비용은 `ls` 한 번, 안 하면 사용자가 «왜 안 되냐»고 물을 때까지 쌓인다.

```bash
ls "<프로젝트>/가이드라인 스크린샷" | grep -v "^[0-9][0-9]_"   # 접두어 없는 것 = 미처리
```

**실패 사례 (2026-08-15, 이 스킬을 만든 그 세션)**: 사용자가 6장을 조용히 넣는 동안 Claude 는
사용자가 경로를 직접 말해준 1장만 처리했다. 사용자가 «왜 매칭이 안 되고 있지?» 라고 물어서야 발각.
**스킬을 만들어놓고 발동 조건을 «사용자가 말할 때»로 잡은 것이 원인이었다.**

세션 시작 시 사용자에게 한 번 알린다: *"폴더는 제가 매번 확인하겠습니다. 그냥 넣어두세요."*

### ① 새 파일 찾기 — mtime 순 정렬 (파일명 절대 믿지 마라)

```bash
cd "<프로젝트>/가이드라인 스크린샷" && ls -la --time-style=+%H:%M:%S | sort -k6
```

- 정렬 축은 **수정시각**이다. 카톡·윈도우 캡처 파일명은 순서를 보장하지 않는다.
- 이미 `NN_` 접두어가 붙은 파일은 처리 완료본이다. **접두어 없는 것만** 후보다.

### ② ★ 이미지를 실제로 연다 (Read 도구) — 추측 금지

**이 단계를 건너뛰면 이 스킬은 쓸모가 없다.** Read 도구는 PNG/JPG를 눈으로 보여준다.
파일명·순서만으로 "아마 DNS 화면이겠지" 하고 이름 붙이면, 한 장만 어긋나도 강의자료 전체가 틀어진다.

열어서 확인할 것:
- 어느 서비스의 어느 화면인가 (상단 로고·메뉴·URL)
- 무슨 상태인가 (설정 전인가 후인가, 에러인가 성공인가)
- **개인정보가 찍혔는가** (결제정보·전화번호·주소·이메일 전체) → 있으면 §5-4

### ③ 대화 맥락과 대조

「직전에 사용자에게 시킨 단계」가 1순위 후보다. 하지만 **본 이미지가 우선한다.**
- 이미지가 예상과 다르면 → 사용자가 순서를 건너뛰었거나 되돌아간 것이다. 표를 고쳐라, 이미지를 우겨넣지 마라.
- 표에 없는 화면이면 → **표에 행을 추가한다.** (실전에서 늘 생긴다: 에러 화면, 중간 확인 팝업)
- 같은 단계를 여러 장 찍었으면 → `04a_`, `04b_` 로 나눈다.

### ④ rename

```bash
cd "<프로젝트>/가이드라인 스크린샷" && mv "KakaoTalk_20260815_1349.png" "04_가비아-A레코드-입력.png"
```

명명 규칙:

```
04_가비아-A레코드-입력.png
│   │      │
│   │      └── 무엇을 하는 화면인지 (동사/상태로 끝맺기)
│   └───────── 대상 서비스·화면 (가비아 / 버셀 / 최종)
└───────────── 강의 진행 순서 2자리
```

- 구분자: 순서와 설명 사이는 `_`, 설명 안에서는 `-`. 섞지 마라 (나중에 파싱한다).
- **공백 금지** — 슬라이드 HTML의 `<img src>` 에 그대로 들어간다.
- 한글 그대로 쓴다. 강의자료는 사람이 읽는 것이고, 실측상 Windows에서 문제없다 (§5-1).

### ⑤ 원장 갱신 — ⬜ → ✅ + 원본 파일명 기록

```markdown
| 04 | A 레코드 입력하는 순간 | `04_가비아-A레코드-입력.png` | ✅ (원본: KakaoTalk_20260815_1349.png) |
```

**원본 파일명을 반드시 남긴다.** 매칭이 틀렸을 때 되돌릴 유일한 단서다.

### ⑥ 사용자에게 한 줄 보고

```
04번으로 받았습니다 — 가비아 A 레코드 입력 화면. 남은 건 05(CNAME), 06(저장 후).
```

길게 쓰지 마라. 사용자는 지금 작업 중이다.

## 4. 강의자료로 뽑기 (전 단계 완료 후)

1. 원장의 ✅ 를 세어 빠진 단계를 먼저 확인 → 빠진 게 있으면 **지금 다시 찍어달라고 한다** (나중엔 재현 불가).
2. `lecture-materials` 스킬 + `visual-design-rules` 스킬을 함께 로드해 슬라이드 HTML을 만든다.
3. 슬라이드 1장 = 단계 1개가 기본. 스크린샷 + 「무엇을 왜」 한 줄 + 「막히면」 한 줄.
4. **함정 슬라이드를 따로 만든다** — 실제로 사용자가 막혔던 지점이 강의의 알맹이다.
   원장에 없던 «추가된 행»(에러 화면)이 바로 그 후보다.

## 5. 함정 (실측)

### 5-1. 한글 파일명 — Bash 는 되고, PowerShell 출력은 깨져 보인다

| 도구 | 한글 파일 조작 | 한글 파일명 «출력» |
|---|---|---|
| Bash (`mv`, `ls`) | ✅ 정상 | ✅ 정상 |
| Write 도구 | ✅ 정상 (부모 폴더 자동 생성) | — |
| PowerShell (`Get-ChildItem`) | 미검증 | ❌ `00_�Կ�����.md` 로 깨짐 |

- **파일 조작·목록 확인은 전부 Bash 로 한다.**
- PowerShell 출력이 깨져 보여도 **파일이 깨진 게 아니다** — 콘솔 코드페이지(949) 문제다.
  여기서 "인코딩이 깨졌다"고 판단해 파일명을 영문으로 바꾸면, 멀쩡한 것을 고치는 헛수고다.

### 5-2. mtime 이 진짜 순서 — 단, 복사하면 리셋된다

카톡·다른 PC에서 파일을 «복사»해 넣으면 mtime 이 복사 시각으로 바뀐다.
mtime 이 전부 같은 분 안에 몰려 있으면 순서 근거로 못 쓴다 → **이미지 내용으로만 판정**하고, 애매하면 물어라.

### 5-3. 표에 없는 화면이 들어오는 게 정상이다

계획대로 흘러가는 실습은 없다. 에러 화면·중간 팝업·재시도 화면이 반드시 낀다.
**표를 지키려 하지 말고 표를 늘려라.** 번호는 소수점 대신 `04b` 처럼 문자를 붙여 뒤 번호를 안 밀리게 한다.

### 5-4. 개인정보가 찍힌 스크린샷

강의자료는 남에게 배포된다. 이미지를 열었을 때 아래가 보이면 **그 자리에서 사용자에게 알린다**:
- 결제정보·카드번호·계좌 / 주민번호·사업자번호 / 전화번호·주소 / 본인 외 타인의 이름·이메일
- 처리: ① 다시 찍기 ② 그 부분이 안 나오게 크롭 ③ 강의에 안 쓰기 — **셋 중 뭘 할지 사용자가 고른다.**
- 판단을 대신 하지 마라. 어떤 정보는 강의에 꼭 필요할 수도 있다(예: 자기 도메인 이름).

### 5-5. 배포되는 프로젝트라면 이 폴더를 배포에서 빼라

스크린샷 폴더가 정적 사이트 루트 안에 있으면 그대로 공개된다.
`.vercelignore` / `.gitignore` 에 `/가이드라인 스크린샷` 을 넣었는지 **폴더를 만든 그 턴에** 확인한다.

## 7. ★ 클로드가 «직접» 앱 화면을 찍어 주석 달기

사용자가 찍어 넣기를 기다리지 않고, **클로드가 앱 창을 직접 캡처해 번호·색 박스를 붙여 보여 주는** 경로다.
「여기 앱에서 스크린샷 찍어서 알려 줘」·「어디 누르는지 보여 줘」·수업자료용 실물 화면이 필요할 때 쓴다.

```
① 화면 확인   앱 배치 도구(get_window_layout)로 «찍을 세션이 지금 화면에 떠 있는지» 본다
② 창만 캡처   bash ~/.claude/skills/screenshot-lecture/scripts/capture-app-window.sh <프로젝트 루트>/스크린샷/<이름>-원본.png [앱 이름]
③ 좌표 잡기   원본을 Read — 축소 표시면 결과에 적힌 배율을 곱해 원본 픽셀로 바꾼다
④ 주석        python3 ~/.claude/skills/screenshot-lecture/scripts/annotate.py <원본> <결과> <표시.json>
              (박스·동그라미 + 번호 라벨, 필요하면 crop·scale 로 확대 — 형식은 annotate.py 맨 위 설명)
⑤ 결과 확인   결과를 다시 Read — stderr 경고(영역 밖·라벨 잘림·색 대체)가 나왔으면 반드시 눈으로 본다
⑥ 정리·전달   §5-4 개인정보 확인이 끝난 뒤 «원본»만 지우고 주석본을 SendUserFile 로 보여 준다
```

- **저장 위치는 §1 의 `가이드라인 스크린샷/` 이 아니라** 전역 규칙의 **프로젝트 루트 `스크린샷/`** 이다.
  §1 은 «사용자가 찍어 넣는 실습 원장», 이 절은 «클로드가 찍는 설명용 캡처»라서 폴더가 다르다.
- 원본을 지우는 것은 클로드가 만든 부산물 정리다(사용자가 넣은 첨부는 지우지 않는다).

| 함정 (실측 2026-10-24) | 막는 법 |
|---|---|
| `screencapture -x` 만 쓰면 **화면 전체**가 찍혀 다른 앱 창(개인 사건 문서)까지 들어갔다 | 창 단위 `-l <창번호>` 만 쓴다 — 스크립트는 창을 못 찾으면 실패로 끝나고 화면 전체로 대체하지 않는다 |
| 사용자가 다른 세션을 보고 있으면 그 세션 내용이 찍힌다 | ①에서 화면 상태를 먼저 확인. 엉뚱한 화면이면 해당 세션을 열어 달라고 한 줄 요청 |
| 같은 앱의 제목줄 조각 창(높이 30px 남짓)이 함께 잡히고, 모니터가 여러 대면 뒤쪽 큰 창이 있을 수 있다 | 400×300 이상 창 중 «가장 앞 창»을 고른다 (스크립트 기준) |
| 파이썬 `Quartz` 모듈이 기본 설치가 아니다 | 창 번호는 swift(CoreGraphics)로 읽는다 |
| `스크린샷/` 이 `.gitignore` 에 없으면 `git add -A` 한 번에 캡처가 커밋된다 | 처음 쓰는 저장소에서는 `git check-ignore 스크린샷/x.png` 로 확인하고, 무시되지 않으면 사용자에게 알린다 |
