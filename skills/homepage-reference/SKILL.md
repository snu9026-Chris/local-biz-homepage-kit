## 2. 분해 절차 — 레퍼런스를 새로 넣을 때 (5단계)

**순서가 중요합니다. 코드부터 열면 «무엇을 보고 있는지» 모른 채 읽게 됩니다.**

### ① 골격 실측 — 코드보다 먼저

헤드리스 브라우저로 **페이지 전체 높이 · 섹션 좌표 · sticky/fixed 요소**를 먼저 잽니다.

```
scrollHeight 가 뷰포트의 5배를 넘고 + height:100vh 짜리 sticky 요소가 있다
   → 스크롤 연동 무대(pinned stage) 구조. ②로.
scrollHeight 가 평범하고 sticky 가 헤더뿐
   → 일반 문서 + 등장 애니메이션(IntersectionObserver). ③만 하면 충분.
```

### ② 상태 전이 추적 — 스크린샷보다 먼저

**스크린샷을 먼저 찍으면 어디를 찍어야 할지 모릅니다.** 스크롤을 250px 단위로 밀며 매 지점의
`data-*` 속성 · 클래스 · 화면에 보이는 레이어 목록을 스냅샷으로 떠서 **달라진 지점만** 남깁니다.
그 목록이 그대로 «촬영 지점표»가 됩니다.

### ③ 스크린샷 — ②가 뽑아준 지점에서만

전이 지점마다 1장. 전환 직후 안정된 프레임을 받으려면 **스크롤 후 1초 이상 대기**합니다.
데스크톱 전부 + 모바일 5~6장 + `prefers-reduced-motion` 1장.

### ④ 번들 역설계 — 라이브러리 → 엔진 → 데이터 순

```
1. 라이브러리 식별   GSAP / framer-motion / lenis / CSS scroll-timeline 중 무엇인가
                     ★ 전부 0건이면 «자작 엔진»이다 — 그때부터가 진짜 분해
2. 엔진 chunk 특정   addEventListener("scroll") · requestAnimationFrame · IntersectionObserver 보유 파일
                     ★ 초기 HTML 에 없는 지연 로드 chunk 를 놓치기 쉽다 — 런타임 계측으로 잡는다
3. 데이터 테이블     타임라인·구간·배율표는 보통 «압축 안 된 배열 리터럴»로 남아 있다. 이게 설계도 원본
```

### ⑤ 증류 — «보이는 것»이 아니라 «만드는 순서»로

설명이 아니라 **절차**로 적습니다. 판정 한 줄 — *「이 문서만 보고 처음부터 만들 수 있나?」*

## 3. 분해용 명령 모음

Playwright 가 전역에 없을 경우 기존 설치본을 직접 참조합니다
(아무 프로젝트의 `node_modules/playwright`, CommonJS 라 `import pkg from …` 형식).
Chrome 은 `channel:'chrome'` 으로 설치본을 그대로 씁니다 — 별도 브라우저 내려받기 불필요.

| 목적 | 수단 |
|---|---|
| 원문 HTML·메타 | `curl -sL -A "Mozilla/5.0" <url>` — 렌더 결과가 아니라 소스 |
| 번들 전량 수집 | HTML 에서 `.js`/`.css` 경로를 뽑아 일괄 `curl` |
| 지연 로드 chunk | `addInitScript` 로 `IntersectionObserver`·`addEventListener` 를 감싸 **생성 스택**을 찍는다 |
| 적용된 CSS 규칙 | CDP `CSS.getMatchedStylesForNode` — 어떤 선택자가 그 값을 줬는지까지 나온다 |
| 소스맵 | `<chunk>.js.map` 직접 시도. 200 이면 원본 코드 복원 — **가장 먼저 해볼 것** |

## 4. 분해할 때 밟은 함정

| 함정 | 증상 | 대응 |
|---|---|---|
| **지연 로드 chunk 누락** | 초기 HTML 의 `<script>` 만 모으면 **엔진 본체가 빠진다** | 런타임 계측으로 스택 추적. 여기선 52KB 엔진이 통째로 빠져 있었다 |
| **「스크롤 리스너가 없다」 오판** | 전역 grep 으로 안 나와 CSS 구동이라 결론낼 뻔 | 위와 같은 원인. **없다고 단정하기 전에 런타임을 계측** |
| **소스맵 미확인** | 미니파이 코드를 손으로 읽느라 시간 낭비 | `.js.map` 을 **먼저** 찔러본다 (이 사이트는 404) |
| **스크린샷 먼저 찍기** | 어디가 전환점인지 모른 채 등간격 촬영 → 핵심 순간 누락 | ②상태 추적을 먼저 |

## 5. 함께 여는 스킬

- **`scroll-scrub-landing`** — 스크럽 영상(스크롤에 물린 비디오)의 **제작**(ffmpeg·프레임 밀도·코덱·모바일 세로본). 레퍼런스에 스크럽 영상이 있으면 재현은 그쪽이 담당
- **`visual-design-rules`** — 재현물을 실제로 그릴 때의 공통 하한선
- **`web-fetch-routing`** — 「가져올지·볼지·조작할지」 레인 결정
